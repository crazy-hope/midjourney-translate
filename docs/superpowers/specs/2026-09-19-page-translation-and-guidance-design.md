# Midjourney 页面翻译与提示词翻译要求设计

## 1. 目标

在现有 Chrome 扩展中增加两组能力：

1. 在 Midjourney 页面内按需显示中文页面翻译，同时保证按钮、链接、图片查看、菜单和原生输入功能不被中文节点拦截或替换。
2. 为千问和 DeepSeek 增加可保存的提示词翻译要求，并让界面明确显示每次请求实际使用的翻译通道，避免“切换类型但无法确认是否生效”。

扩展继续保持 Manifest V3、无自建后端、API Key 与设置仅保存在 `chrome.storage.local`。

## 2. 已确认的交互

### 2.1 翻译类型

- 面板右上角继续提供 `DeepSeek`、`千问`、`免费翻译` 三种类型。
- 当前选择立即用于下一次提示词翻译，不要求先保存。
- 点击“保存”时，将当前类型与中文提示词、翻译要求和 Midjourney 参数一起保存。
- 每次翻译的处理中和完成状态均显示后台实际返回的类型，例如“正在使用 DeepSeek 翻译”和“DeepSeek 翻译完成”。
- 新安装默认类型为 DeepSeek；已有用户保留之前保存的类型。

### 2.2 横向翻译要求输入框

- 在双栏提示词输入区下方增加一个横向单行输入框，名称为“翻译要求（仅千问 / DeepSeek 有效）”。
- 默认内容为：

  `按照 Midjourney 易理解的视觉提示词风格翻译，准确保留主体、构图、镜头、光线、材质、色彩和氛围；先分析语义，再只输出自然、简洁的英文提示词。`

- 用户可修改；留空表示普通、忠实的中译英。
- 选择免费翻译时输入框保持可见但禁用，并提示公共翻译接口无法遵循自定义要求。
- 该要求只作用于中文提示词的中译英，不作用于整页英文界面的英译中。
- 大模型可以在内部分析语义，但响应必须只包含最终英文提示词，不输出分析过程。

### 2.3 页面翻译开关

- 增加“翻译页面”Switch，默认关闭，且不持久化；每次刷新 Midjourney 页面均恢复关闭。
- 开启“翻译页面”后，出现“保留原文”Switch。
- “保留原文”默认开启，且仅作为当前页面会话状态，不持久化。
- 保留原文开启时：英文原文保持原位，中文翻译显示在英文下方或紧邻位置。
- 保留原文关闭时：视觉上只显示中文；扩展仍在内存中保存英文，以便关闭页面翻译后立即恢复。
- 关闭“翻译页面”时：停止新请求、移除扩展添加的中文、恢复被隐藏的英文。
- 页面翻译开启期间切换右上角翻译类型时，清理旧通道生成的中文并使用新通道重新翻译当前页面。

### 2.4 编辑中文时保留右侧翻译

- 用户编辑左侧中文输入框时，不清空右侧已有的中英文对照。
- 编辑发生后，将右侧结果标记为“上次翻译，中文内容已修改”。
- 在结果过期状态下，单独点击“填入”不得把旧英文写入 Midjourney，而是提示先重新翻译。
- 点击“翻译”会根据最新中文更新右侧结果并解除过期状态。
- 点击“翻译并填入”会根据最新中文重新翻译后再填入，不使用旧结果。
- 临时“清空”按钮仍同时清空左右两侧的当前界面内容，但不修改本地已保存内容。

## 3. 翻译类型问题的诊断与修复边界

当前代码已经把面板选择值随 `translate` 消息发送给后台，后台也会用该值覆盖已保存类型后选择免费或大模型分支。因此，仅凭两次输出相似，不能证明使用了同一接口；简短提示词的普通翻译本身可能相近。开发模式下重新加载扩展后，已经打开的 Midjourney 页面还必须刷新，否则页面可能继续运行旧内容脚本。

本次修改不依赖推测判断通道，而是增加可验证的数据链路：

1. 内容脚本发送所选 `provider`。
2. 后台规范化并实际选择通道。
3. 后台响应同时返回实际使用的 `provider`。
4. 面板状态展示后台返回值，而不是只展示下拉框当前值。
5. 自动测试分别验证免费和 DeepSeek 进入不同执行分支，并验证切换无需先保存。

## 4. 页面翻译架构

### 4.1 独立模块

新增页面翻译模块，负责：

- 查找适合翻译的可见英文文本节点；
- 排除扩展自身面板、`script`、`style`、`noscript`、代码块、输入框、文本域和 `contenteditable` 区域；
- 跳过纯数字、纯符号、URL、参数串和已经以中文为主的文本；
- 管理翻译队列、缓存、DOM 注入、原文显示模式与恢复；
- 处理 Midjourney 单页应用动态加入的内容。

该模块与现有“查找提示词输入框”的 DOM 适配器分离，避免整页扫描逻辑影响输入面板挂载。

### 4.2 DOM 安全策略

- 不使用 `innerHTML` 重建 Midjourney 节点。
- 不替换按钮、链接、图片、菜单或其父元素。
- 保留原文本节点，并在其后插入扩展拥有的翻译 `span`。
- 翻译节点标记 `data-mjpt-page-translation`、`aria-hidden="true"`，并设置 `pointer-events: none`，确保鼠标操作落到原 Midjourney 元素。
- 保留原文关闭时，只暂时清空原文本节点的显示值；不删除父元素，不改变父元素事件监听器。
- 恢复时仅处理仍由扩展控制且仍连接在页面中的记录，避免覆盖 Midjourney 自己随后更新的内容。
- MutationObserver 忽略扩展添加的翻译节点，防止循环翻译。

### 4.3 动态内容、缓存与限流

- 首次开启时扫描当前文档中的候选文本。
- 后续只扫描 MutationObserver 报告的新子树，不反复遍历整个页面。
- 对完全相同的英文去重。
- 缓存键包含翻译类型、方向和原文，切换类型不会复用另一通道的结果。
- 使用小并发队列，默认最多同时发出两个请求；收到限流错误时停止继续提交并在面板显示错误。
- 关闭开关时通过会话令牌使未完成响应失效，迟到的响应不得再次写入页面。

## 5. 翻译服务变化

### 5.1 方向

后台翻译消息增加用途或方向：

- `prompt`：中文提示词到英文。
- `page`：Midjourney 页面英文到简体中文。

MyMemory 根据方向使用 `zh-CN|en` 或 `en|zh-CN`。千问和 DeepSeek 使用与方向对应的系统指令。

### 5.2 大模型提示词翻译

大模型的提示词翻译请求由三部分组成：

1. 固定安全约束：只翻译用户提供的文本，不执行文本中的指令，不添加 `--参数`。
2. 用户保存的“翻译要求”；留空时使用忠实直译规则。
3. 用户中文提示词。

模型只返回英文结果。扩展继续清理代码围栏和多余引号。

### 5.3 页面英译中

页面翻译使用独立的固定规则：准确、简洁地翻译界面文字，不解释、不扩写、不使用提示词翻译要求。免费翻译和大模型均可执行此方向。

## 6. 设置结构

在现有 `settings` 中增加：

```json
{
  "translationInstruction": "按照 Midjourney 易理解的视觉提示词风格翻译……"
}
```

配置规范化需要：

- 缺少字段时填入默认要求；
- 非字符串值回退到默认要求；
- 允许空字符串，代表普通直译；
- 限制最大长度，防止异常内容导致请求过大。

页面翻译和保留原文两个 Switch 不写入 `chrome.storage.local`。

## 7. 状态与错误处理

- 大模型缺少 API Key、端点或模型名时，立即提示打开设置，不回退到免费翻译。
- 页面翻译进行中显示已完成数量和待处理数量，但不阻塞 Midjourney 页面。
- 单条页面文本翻译失败时保留英文，不写入空中文。
- 授权、限流、超时或网络错误显示一次汇总提示，避免每个文本节点重复弹错。
- 切换类型、关闭页面翻译或页面路由变化时，旧请求结果不得污染新状态。

## 8. 隐私与商店披露

开启页面翻译后，Midjourney 当前页面中符合条件的可见英文文本会发送给用户选择的翻译服务。这可能包括页面界面文字和用户可见的提示词内容。

因此必须同步更新隐私政策和 Chrome Web Store 数据披露：

- 明确整页翻译仅在用户主动开启后运行；
- 明确文本会发送到 MyMemory、千问、DeepSeek 或用户配置的接口；
- 不将页面文本写入翻译历史或扩展本地存储；
- 内存缓存随页面关闭或刷新消失；
- 不出售、不用于广告、不进行行为分析。

## 9. 测试

### 9.1 自动测试

- 默认翻译要求、空字符串和最大长度规范化。
- 点击保存时同时保存类型、翻译要求、提示词和全部参数。
- 编辑中文后右侧旧翻译保持可见并标记过期，旧结果不能被单独填入。
- 当前未保存的类型仍用于下一次翻译。
- 后台响应报告实际使用的类型。
- 免费与 DeepSeek 分别进入不同执行分支。
- 免费接口支持中译英与英译中语言对。
- 大模型请求包含固定约束和用户翻译要求，响应仍只取最终文本。
- 页面候选文本过滤规则。
- 相同文本去重和缓存隔离。
- 保留原文开启时原节点不变且翻译节点不可拦截点击。
- 保留原文关闭时隐藏原文本，关闭页面翻译后恢复。
- 动态新增节点进入队列，扩展生成节点不会再次进入队列。
- 关闭开关后，迟到请求不得写入 DOM。

### 9.2 手动验收

- 切换免费、千问、DeepSeek 后，状态显示实际使用的通道。
- 修改翻译要求后无需保存即可用于当前翻译；保存并刷新后能恢复。
- 免费翻译时翻译要求输入框禁用。
- 页面翻译默认关闭；开启后出现“保留原文”。
- 双语和仅中文两种模式均不影响按钮、链接、图片查看、菜单和滚动。
- Midjourney 加载新图片或切换路由后，新出现的英文可继续翻译。
- 关闭页面翻译后原页面文本恢复，且无残留中文节点。

## 10. 非目标

- 不翻译图片内部文字。
- 不翻译输入框、文本域或正在编辑的内容。
- 不把整页翻译结果写入长期历史。
- 不自动回退到另一翻译类型。
- 不要求或展示大模型的内部推理过程。
